# 这个插件能干什么、不能干什么

> 一句话：**自带一份 GNU PSPP 引擎的 SPSS 式统计工作台，装在 DeepSeek Harness 的右侧栏里；面板点得到的过程，对话里的模型也能用工具对同一份数据做一遍。**
> 细节（每个过程的表长什么样、字段含义、实现日期）在 [FEATURES.md](FEATURES.md)；逐版过程在 [CHANGELOG.md](CHANGELOG.md)；引擎缺什么、原文怎么说在 FEATURES 第 13 节。

## 1. 装在哪、怎么装

- 形态：DSH 插件（bundle `dsh-analytics-pspp`），在侧栏注册一个页签「统计分析」，路由 `/analytics`，数据落在 `~/.dsh/analytics`。
- 引擎：插件目录内自带预编译 PSPP（`engine/<平台>-<架构>/`，Linux/macOS/Windows 各约 23 MB），**不连接系统里另装的 PSPP**，也不需要用户装 PSPP。
- 安装：`node scripts/install.mjs <profile> --apply`（下 Release 的 `.tgz`、按 `SHA256SUMS` 校验、装进 profile 并把包名加进 `dsh.profile.bundles`）；之后在「设置 → 插件」里关一次再开。
- 卸载：从 `dsh.profile.bundles` 移除该包名即可；`~/.dsh/analytics` 里的数据集与复现包要自己删。

## 2. 面板里能点到的

按菜单分组（数字随版本变化，以当前版本为准）：

- **文件**：打开数据（sav/csv/xlsx/ods/dta）、保存、另存、导入文本向导、导出输出（Word/Excel/PDF/ODT/HTML）、导出报告成册、导出复现包。
- **编辑 / 视图**：数据网格的剪切/复制/粘贴/清除、转到个案/变量、撤销重做、表格样式、网格线与工具栏开关、结果句子、快捷键一览。
- **数据**：数据体检、新建变量、批量导入值标签、插入/删除个案、排序个案、选择个案、加权个案（与关闭）、拆分文件、随机抽样、重构（个案转变量 / 变量转个案）、合并文件（添加个案 / 按关键变量）、转置、标识重复个案、标识异常个案。
- **转换**：计算变量（带表达式构建器）、重新编码为不同变量、自动重新编码、汇总、计数、排秩、替换缺失值、定义多选题与多选题面板。
- **分析**：描述统计（频率/描述/探索/交叉表）、比较平均值（均值/单样本 t/独立样本 t/配对 t/单因素 ANOVA/两两比较）、一般线性模型（单变量）、相关（双变量/偏相关）、回归（线性/二元 Logistic/多项 Logistic/有序 Logistic/泊松/权重估计/二阶段最小二乘/曲线估计）、降维（因子/对应分析/多重对应分析/多维标度/快速聚类）、刻度（可靠性）、对数线性、非参数检验（卡方/二项式/K-S/游程/Wilcoxon/符号/Mann-Whitney/Kruskal-Wallis/中位数/Jonckheere-Terpstra/Friedman/McNemar/Cochran Q/Kendall W）、表（自定义表/基线表/组间比较表）、功效与样本量、ROC、分类（系统聚类/判别）、时间序列（移动平均/指数平滑）、生存分析（Kaplan–Meier/Cox/竞争风险/生命表/均值与百分位）、质量控制（X̄–R 控制图/帕累托图）、缺失值分析。
- **图形**：条形图/帕累托/直方图/箱线图/P-P 与 Q-Q/折线/饼图/面积/散点（可按类别着色、可叠拟合线）/误差线、图表拼版、图表编辑（改标题副标题、重绘为另一种图、导出 PNG 1×–4×）。
- **实用程序**：语法编辑器与模板库、运行历史、分布计算器、查找过程、设置。
- **帮助**：跟着做一遍（示例数据九步）、打开示例数据、快捷键、关于。

## 3. 引擎没有、但插件自己算的

PSPP 2.1.3 里这些过程**整个不存在**（原文见 FEATURES §13.1），插件自己实现，因此没有「引擎不支持」的占位提示：

生存分析（Kaplan–Meier、Cox、分层 Cox、时依协变量、竞争风险、生命表、均值与百分位）、判别分析、多项与有序 Logistic、泊松回归、偏相关、多选题频数/交叉表、P-P 与 Q-Q 图、曲线估计（11 模型）、多维标度、一般对数线性、对应分析与多重对应分析、系统聚类与树状图、时间序列平滑、功效与样本量、X̄–R 控制图与帕累托图、分布计算器、随机区组/因子设计的对比与事后检验（引擎只给单因子 ONEWAY 时）。

每条都自带独立校验（闭式解、恒等式、或与引擎能算的那一支互校），细节在 FEATURES 各节末尾的「怎么验」。

## 4. 不能干什么

- **引擎没实现的统计方法**：混合/多变量模型、ANCOVA（GLM 的 `WITH`）、决策树（TREE）、REPORT/CODEBOOK、非线性回归（NLR）、复杂抽样、多重插补、分层对数线性、ARIMA/季节分解、加权 Cox 的稳健方差。菜单里点这些会给出**原因 + 替代做法**，不会静默算错。
- **语法层限制**：`REGRESSION` 只认 `/METHOD=ENTER`（`STEPWISE`/`BACKWARD`/`FORWARD`/`/ENTER=`/`/TEST=` 全部报错，0.55.2 用真引擎逐条验过），所以面板不提供逐步回归入口。
- **界面宽度**：侧栏 380–520 px，SPSS 那种右侧竖排选项按钮与多栏子对话框放不下 ⇒ 只保证**条目重叠处的行为一致**，不逐像素复刻 SPSS 的 207 个菜单条目。
- **界面语言**：外壳（菜单/对话框/提示/通知/导出外壳）有中英两套；**表注正文、建议正文、引导正文、变量名与数据值保持中文/原样** —— 它们含具体数字与变量名，整句翻译会失真。
- **真机端到端**：`npm test` 的界面部分跑在 jsdom 里；真浏览器里的版式（菜单/子菜单会不会被 380–520 px 的侧栏裁掉、控制台有没有报错）由 `npm run e2e` 单独覆盖（真 Chromium + 真引擎，480 px 与 380 px 两个宽度）。它不在 `npm test` 里，没装 playwright 时 skip。**像素观感与滚动手感仍只靠人看截图**。

## 5. 怎么验

```bash
npm test        # 66 个套件，全绿时 970 条 ok 断言（不装 poppler 969）
npm run e2e     # 真浏览器 7 条（真 Chromium + 真引擎，不进 npm test；没装 playwright 时 skip）
```

- 纯函数套件（图表模型、Word/Excel XML、字典、统计量、缺失值、聚类、生存、判别…）+ jsdom 面板套件 + **真引擎**套件（smoke/routes/flow/poll/repro 直接跑包内 PSPP）。
- CI 四条腿：`unit`（ubuntu，纯函数 + jsdom + 打包自检）、`e2e`（ubuntu，真 Chromium 跑 `test/e2e.mjs`，截图留 artifact）、`engine`（ubuntu，真引擎 smoke/routes/flow/tools/weight/pdf-notes + poppler 回读 PDF）、`engine (矩阵)`（ubuntu / windows-latest / macos-15 各一份，下载该平台的引擎产物后跑同一批真引擎套件）。`pdf-notes` 在 Windows 与 macOS 上因为没有 `pdftotext` 会打一行 skip 并 exit 0，由 `engine` 那条腿的 poppler 回读补上。
- 断言纪律：新增断言必须做过删除式变异验证（把修复删掉要变红）。

## 6. 数据与隐私

- 全部计算在**本机**的 PSPP 进程里完成；插件不发任何数据到外部。
- 唯一的外发请求是「帮助 → 检查更新…」查 GitHub Release 的版本号，可以直接不用。
- 文件读写过一道白名单（`lib/paths.js`）：默认允许 `~`、工作目录、`/mnt`、`/tmp`；`~/.dsh`、`~/.ssh`、`~/.gnupg` 硬拒（那里放的是凭据与密钥），越界会给出可操作的中文提示，也可以把目录加进设置的白名单。
